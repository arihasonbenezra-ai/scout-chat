# Ezzy Roadmap

Ordering rule (directive §33): for every phase, ask — does this make Ezzy know the user better, give better advice, help the user act, create proprietary data, or strengthen the feedback loop? If no to all five, it's out of scope for that phase.

## Phase 0 — Immediately, outside normal roadmap sequencing

**Close the open AI proxy** ([EZZY_ARCHITECTURE.md](EZZY_ARCHITECTURE.md) §1). This is a live security/cost bug, not a feature — it should ship before or alongside anything else regardless of roadmap priority.

Also cheap and immediate: add a `.gitignore` (no secrets are committed today, but nothing is stopping it), and commit the Supabase schema as SQL migrations so it exists somewhere other than "live in production."

## Phase 1 — Career Brain v0 (highest priority)

- `career_profile` + `career_claims` tables ([EZZY_CAREER_BRAIN.md](EZZY_CAREER_BRAIN.md)).
- Server-side extraction call wired into Resume Feedback (richest source, already exists) first, then Practice/STAR/Mock.
- "What Ezzy knows about you" read-only panel with evidence + fact/inference/hypothesis labeling ([EZZY_UX_STRATEGY.md](EZZY_UX_STRATEGY.md)).
- Minimal analytics (activation, mode usage, return rate) — needed to judge whether Phase 1 actually worked before investing further.
- **Why first**: every later phase (assessment, adaptive coaching, job matching, daily coach) depends on this data existing. Nothing else on the roadmap is buildable without it, and the raw material (resumes, transcripts) is already flowing through the product today unused.
- **Explicitly not in Phase 1**: comp data, job matching, market intelligence, any proactive notification.

## Phase 2 — Adaptive Interview Coach

- Turn Mock/Practice/STAR debriefs (already generated by the model today, currently discarded) into stored competency scores per session.
- Longitudinal readiness snapshot (EZZY_CAREER_BRAIN.md v1) — "you're improving" backed by real history, not gamification.
- Light adaptivity: bias the next Practice/STAR question selection toward the weakest tracked competency, using the existing prompt-based approach (no new agent framework needed — this is one more piece of context injected into the existing coaching prompt).
- **Why second**: it's the most direct extension of the product's current core strength (interview practice) and produces the outcome data (§37/§38) — improvement over time — that's the strongest retention and differentiation lever available before any market-facing features exist.

## Phase 3 — Career Intelligence (job matching, gated on Phase 1–2 retention data)

- Start with **user-pasted job descriptions**, not scraped listings: "should I apply?" analysis using Career Brain + pasted JD (zero data-acquisition cost, zero legal exposure, reuses the extraction pipeline already built).
- Skill-gap analysis against a pasted JD.
- Compensation intelligence only via a licensed data source, not scraped or LLM-guessed — until that's budgeted, keep comp claims off the product entirely rather than fabricating them (directive §26).
- **Gate**: don't start this phase until Phase 1–2 show that users actually return to and value the Career Brain surfaces. If they don't, job matching built on top of an unused/unengaged profile won't be trusted either.

## Phase 4 — Proactive Career Coach

- Daily "what should I do today" surface — sequenced *after* there's a real backlog of evidence-backed items to prioritize (interviews tracked, weaknesses tracked, goals tracked from Phase 1–3).
- Requires new infra not present today: email/push notifications, a scheduling layer.
- Career Missions (multi-week adaptive plans) — only once there's enough usage data to make "adaptive" mean something more than a hardcoded template.

## Phase 5 — Agentic Career Operating System

Treated as directionally aspirational, not a committed phase. Continuous market monitoring and autonomous job discovery are real, valuable ideas, but they're a standalone data-and-agent product in their own right (see EZZY_ARCHITECTURE.md §5) and shouldn't be scoped until Phases 1–4 have validated that users trust and act on Ezzy's advice at all. Revisit this phase's shape entirely once that's known — don't pre-commit to the 7-agent architecture in the original directive today.

## Cut or indefinitely deferred, with reasons

| Idea | Why deferred |
|---|---|
| Graph database / Career Graph as literal graph infra | Relational + JSONB covers the same relationships at current scale (EZZY_ARCHITECTURE.md §2) |
| Multi-agent orchestration framework | No current workflow needs agent coordination; adds ops overhead for no present benefit |
| Autonomous job/market scraping | Legal/ToS risk, needs licensed data, own roadmap — start with user-pasted JDs instead |
| Comp data | No licensed source budgeted; do not fabricate with LLM guesses |
| Daily coach / notifications / missions | No backlog data to prioritize yet; sequenced in Phase 4 |
| Connected accounts / LinkedIn import | Existing sources (resume, transcripts) already unused — exhaust those first |
